# Project Deployment Plan

This document outlines the deployment strategy for this project, detailing how to host the **Backend on Railway** and the **Frontend on Vercel**. Since both are housed in a single monorepo, we'll take advantage of directory-specific configurations for both platforms.

---

## 1. Backend Deployment (Railway)

We will deploy the Python/FastAPI backend on [Railway.app](https://railway.app/), which provides excellent support for Python services and docker-less deployments.

### Prerequisites
- Create a [Railway](https://railway.app/) account.
- Link your GitHub account to Railway.

### Steps to Deploy
1. **Create a New Project:** Go to the Railway dashboard, click **"New Project"**, and select **"Deploy from GitHub repo"**.
2. **Select Repository:** Choose `FRST-PROJECT` (the repository for this app).
3. **Configure Service Settings:**
   Once the service is created, go to the **Settings** tab for that service.
   - **Root Directory:** Set this to `/backend`. This tells Railway to ignore the frontend and only install `requirements.txt` from the backend directory.
   - The start command is already configured automatically by the `railway.toml` file located in the backend directory!
4. **Environment Variables:**
   Go to the **Variables** tab and add the necessary environment variables:
   - `GROQ_API_KEY`: Your Groq LLM API Key (required for AI features).
   - `CORS_ORIGINS`: The URL of your Vercel frontend (e.g., `https://zomato-ai-frontend.vercel.app`). *Note: you will get this URL after deploying the frontend on Vercel. Once you have it, add it here in Railway to allow your frontend to communicate with your backend.*
5. **Generate a Public URL:**
   Go to the **Settings** tab, scroll to **Networking**, and click **"Generate Domain"**. 
   > **Important:** Save this URL. You will need it for the frontend configuration.

---

## 2. Frontend Deployment (Vercel)

We will deploy the Vite/React frontend on [Vercel](https://vercel.com/), which provides native support for Vite and blazing-fast global CDNs.

### Prerequisites
- Create a [Vercel](https://vercel.com/) account.
- Link your GitHub account to Vercel.

### Steps to Deploy
1. **Import Project:** Go to the Vercel dashboard, click **"Add New..."** -> **"Project"**, and import `FRST-PROJECT` from your GitHub account.
2. **Configure Project:**
   In the configuration screen before deploying, set the following:
   - **Framework Preset:** Vercel should automatically detect **Vite**.
   - **Root Directory:** Click **Edit** and select the `frontend` folder.
   - **Build and Output Settings:** Leave as default (Build Command: `npm run build`, Output Directory: `dist`).
3. **Environment Variables:**
   Expand the **Environment Variables** section and add:
   - `VITE_API_URL`: Set this to the public URL generated by Railway in the previous step (e.g., `https://your-railway-app.up.railway.app`). Ensure it does **not** have a trailing slash.
4. **Deploy:** Click **Deploy**. Vercel will build and host your frontend, providing you with a live production URL.

---

## 3. Post-Deployment Verification
- Visit your Vercel URL to view the live web application.
- Try searching for a restaurant or interacting with the UI.
- Ensure the API requests are successfully routed to your Railway backend (you can monitor logs in both the Vercel and Railway dashboards to verify traffic).

### Updating Code
Because this repository is connected to both platforms, pushing to the `main` branch on GitHub will automatically trigger:
- A new build on Vercel (for the frontend).
- A new build on Railway (for the backend).
